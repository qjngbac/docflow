## 2. 每一笔改了什么、为什么、怎么验证

### 修复 1（最关键）：协作恢复点 / 历史回滚 / 自动压缩全部失效

- **现象**：点「立即创建恢复点」报错；面板「恢复点序号」长期为 0、「最近创建时间」停在很久以前、「待整理的修改」持续增长。
- **根因**：`docflow-collab/src/store.js` 的 `trimHistory()` 里把 `LIMIT` 写成了绑定参数：
  ```js
  'SELECT id FROM crdt_checkpoint_history WHERE doc_id = ? ORDER BY id DESC LIMIT ?', [documentId, limit]
  ```
  MySQL 预处理协议**拒绝 LIMIT 用绑定参数**，直接报
  `ER_WRONG_ARGUMENTS: Incorrect arguments to mysqld_stmt_execute`。
  而 `trimHistory` 是 `checkpoint()` 的**最后一步**，于是手动建点、`restoreCheckpoint`（历史回滚）、以及 `onStoreDocument` 里的**自动压缩全部整笔回滚**。
- **改动**：改为 `LIMIT ${limit}`，与同文件 `listHistory()`（一直可用）保持一致；`limit` 已由 `Math.max(2, Math.min(100, …))` 收敛为 2~100 的整数。
- **验证**：在真实 MySQL 上把 `checkpoint()` 的 7 条 SQL 放在事务里逐步重放（末尾 `ROLLBACK`，不改数据）——修复前失败于第 6 步，修复后 7 步全过。另加回归测试断言不出现 `LIMIT ?`。
- **上线注意**：修复生效后**第一次压缩会把积压的 `crdt_update` 合并进快照并删除这些行**。这是设计行为，不是丢数据；但会是一次较大的事务，建议先备份。

### 修复 2：`@hocuspocus/server` 4.x 的 API 误用

- **现象**：删除文档 / 权限变更后的「关闭协作连接」、版本回滚的「替换正文」失败。
- **根因**：`Server` 只是外层包装对象，`documents` / `closeConnections` / `unloadDocument` 实际在 `server.hocuspocus`（Hocuspocus 实例）上。
- **改动**：`src/server.js` 三处改为 `server.hocuspocus.*`；断连逻辑抽到新文件 `src/document-eviction.js` 的 `createDocumentEvictor()`，文档不在内存时安全空操作。
- **验证**：新增 4 个测试（含"文档未加载时空操作不抛错"），外加一条直接断言依赖结构的契约测试。

### 修复 3：失败提示含义错误 + 缺可定位日志

- **现象**：关闭连接、替换正文失败时，也统一提示成 "CRDT checkpoint validation or compaction failed"。
- **改动**：
  - `admin-server.js` 新增 `failureMessage(path)`，按操作区分失败文案；
  - `admin-server.js` 的 catch 记录真实的 `method + path + 异常原因`；
  - `CrdtCheckpointService.java` 给 6 个 Admin 调用加上中文操作标签，非 200 与网络异常都输出 warn 日志（`action/method/path/status` + 上游响应截断 300 字符）；
  - Java 抛给前端的文案从英文改成中文（原英文会被前端 `friendlyMessage` 吞成通用 409 文案）。
- **安全约束**：日志与响应**都不打印共享密钥，也不打印请求体**。
- **验证**：新增测试断言"不同操作文案不同"且日志中不含密钥。

### 修复 4：批注面板筛选下拉的文字被裁

- **根因**：`* { box-sizing: border-box }` + 全局 `.input { padding: 10px 14px }` + 组件里 `.comment-tools .input { height: 32px }` 三者叠加 → 内容区只剩 10px，文字上下被切。
- **改动**：`DocEdit.vue` → `.comment-tools .input{height:32px;min-height:32px;min-width:0;padding:0 10px;line-height:1.2}`。

### 修复 5：协作者表单三个控件高矮不一

- **根因**：`.collaborator-form` 只声明了列宽，没约束控件高度（输入框 ~44px、下拉 ~39px、按钮 32px）。
- **改动**：`DocEdit.vue` → 该表单统一 36px 高度 + `align-items:center`；输入框/下拉垂直内边距置 0（同样为避开"固定高度 + 大 padding 裁字"的坑）。

### 修复 6：登录态被动失效时没有任何提示

- **根因**：`api/index.js` 跳转登录页时带了 `?reason=expired`，但全项目没有任何地方读取它。
- **改动**：`Login.vue` 挂载时消费该参数，提示「登录已过期，请重新登录」。

### 修复 7：多条提示完全重叠在一起

- **现象**：导出 Word 触发登出后，右上角出现两条提示**叠在同一位置**，互相遮挡。
- **根因**：`assets/main.css` 里 `.toast { position: fixed; top: 20px; right: 20px }`——每条提示都被固定到同一个坐标，出现第二条时必然完全重叠。
- **改动**：新增 `.toast-container`（`position:fixed` + `flex-direction:column` + `gap`），`toast.js` 把提示统一追加进这个容器；`.toast` 去掉自身定位。顺便限制最多同时显示 4 条（避免连续失败时刷屏）。
- **验证**：新增 `src/utils/toast.test.js`，断言"两条提示是同一容器的两个子节点"以及"只保留最近 4 条"。

### 修复 8：导出失败时看不到真实原因（blob 错误体读不出来）

- **现象**：导出失败只提示通用的「登录状态已失效，请重新登录」，无法得知后端到底为什么拒绝。
- **根因**：导出接口用 `responseType: 'blob'`，出错时**响应体也是 Blob**，而拦截器里读的是 `error.response.data.message` → 永远是 `undefined` → 只能退化成通用文案。
- **改动**：`api/index.js` 新增 `readBlobMessage()`，当错误体是 Blob 时读出文本并解析 JSON，取出后端真正的 `message`。
- **价值**：这条改动让"导出为什么 401"这类问题**从此可直接从提示上看出来**，不用再翻服务器日志。

### 修复 9：续期失败就清空登录态（含限流/网络抖动）

- **现象**：任意请求续期失败 → **整个会话被清掉，直接退出登录**。
- **根因**：`retryAfterRefresh()` 里 `catch` 无条件调用 `expireLogin()`。而 `/api/v1/auth/refresh` 属于 **auth 限流桶（默认 30 次/分钟）**，被限流时返回 **HTTP 429**；5xx、网络超时同样会走到这里——这些都不该等于"会话失效"。
- **改动**：新增 `isSessionRejected()`，**只有服务端明确判定会话失效（HTTP 401，或 HTTP 200 里带业务码 401）才登出**；限流、5xx、网络抖动只提示错误、保留登录态。
- **说明**：这是本次"导出即登出"的**重点嫌疑**，但尚未最终确认——见第 9 节。

### 修复 10（重要）：文档导出接口恒返回 401 —— 已实测确认并修复

- **现象**：点「导出 Word 文档」，接口返回 **401**，前端尝试续期失败后**直接退出登录**。本地与线上表现一致。
- **实测确认**（用临时实例 + 真实令牌打接口）：**带着刚签发的有效访问令牌导出自己的文档，依旧返回 401**「请先登录后再操作」；而同一令牌调同步接口（如创建文档）一切正常。→ 说明**与会话过期、令牌失效无关，是确定性缺陷**。
- **根因**：导出接口返回 `Callable`（异步），Spring MVC 会在 **ASYNC 派发**时再次经过安全过滤器链；而 `JwtAuthFilter extends OncePerRequestFilter`，默认**跳过 ASYNC 派发**（`shouldNotFilterAsyncDispatch()` 返回 true）。同时 Spring Security 6 的 `SecurityContextHolderFilter` 只从存储读取上下文、不会写回，于是 ASYNC 派发时安全上下文为空，`anyRequest().authenticated()` 判定失败 → 401。
- **改动**：在 `JwtAuthFilter` 中重写 `shouldNotFilterAsyncDispatch()` 返回 `false`，让令牌校验在 ASYNC 派发时也执行一次。
- **修复后实测**：导出 docx → **HTTP 200 + `application/vnd.openxmlformats-...` + 字节头 `PK\x03\x04`（真 docx）**；导出 PDF → **200 + `%PDF-`**；不带令牌仍是 401（正确）。
- **影响面**：所有返回 `Callable` 的接口（当前是 `/docs/{id}/export/docx` 与 `/docs/{id}/export/pdf`）原本都不可用。

### 修复 11（重要）：导出失败会下载到"假文件"

- **现象**：导出失败时，用户拿到的不是一个错误提示，而是**一个内容是 JSON 的 .docx/.pdf 文件**。
- **实测确认**：导出不存在的文档 → **HTTP 200 + `Content-Type: application/json` + `{"code":404,...}`**；导出无权文档 → **HTTP 200 + `{"code":403,...}`**。这是因为项目统一约定「业务错误用 HTTP 200 + 业务错误码」返回，而前端导出请求用的是 `responseType: 'blob'`，会把这段 JSON 当成文件交给下载逻辑。
- **改动**：`docflow-web/src/api/index.js` 的响应拦截器新增判断——**当响应体是 Blob 且 `Content-Type` 为 JSON 时，先解析出业务错误码并按错误抛出**（`code !== 200` 即抛），不再进入下载流程。
- **修复后预期**：导出失败时用户看到的是真实原因（如「你没有查看此文档的权限」），而不是下载到一个假文件。
- **注意**：**没有改动后端的状态码约定**（保持 HTTP 200 + 业务码），只在前端做识别，避免影响全线接口契约。

## 4. 上传与部署注意事项

### 4.1 三份产物必须同版本
后端 jar、前端 dist、协作服务代码要来自**同一次提交状态的工作区**。混版本会出现"前端调用了后端没有的接口"这类问题。

### 4.2 协作服务依赖必须用 `npm ci`，禁止 `npm install`

`docflow-collab/package.json` 里三个依赖写的是 **`"latest"`**：

```json
"@hocuspocus/extension-redis": "latest",
"@hocuspocus/server": "latest",
"@hocuspocus/transformer": "latest",
```

`package-lock.json` 钉住的是 **4.3.0**——**本次修复中的第 2 项正是针对 4.3.0 的 API 结构**。
所以服务器上必须用 `npm ci` 严格按锁文件安装，装完务必核对：

```bash
node -e "console.log(require('./node_modules/@hocuspocus/server/package.json').version)"
# 必须输出 4.3.0；若是别的版本，第 2 项修复的假设就不成立了
```

### 4.3 服务器 env 必须显式覆盖的 5 项（不覆盖会有真实风险）

| 变量 | 代码默认 | 不覆盖的后果 |
|---|---|---|
| `APP_ENV` | `development` | 与下一行组合会泄露验证码 |
| `APP_VERIFICATION_DEBUG_CODE` | `true` | ⚠️ **高危**：若 `APP_ENV` 不是 production 且邮件未启用，`POST /api/v1/auth/password-reset/request` 会把验证码**直接写在接口响应里** → 任何人都能重置任何邮箱的密码 |
| `FILE_PUBLIC_ACCESS_ENABLED` | `true` | `/files/**` 匿名可访问，附件与头像无需登录即可拉取 |
| `CRDT_ADMIN_SECRET` | `docflow-local-admin`（Java 与 collab **两端是同一个默认值**） | 建点 / 回滚 / 替换正文 / 断连的管理接口使用公开默认密钥。1235 端口只监听回环，风险有限，但不该这样上线 |
| `AUTH_IDLE_TIMEOUT_MINUTES`、`AUTH_REMEMBER_DAYS` | 720 / 90 | 服务器若仍写着旧值（30 / 30）会覆盖本次调整 |

依据：`AccountSecurityService.issueCode()` 只在「邮件未启用 && debugCode && 环境非 production」三个条件同时成立时才回传 `debugCode`。

在服务器上做**不打印密钥**的自检：

```bash
sudo bash -c 'set -a; . /etc/docflow/server.env; set +a; for k in APP_ENV APP_VERIFICATION_DEBUG_CODE FILE_PUBLIC_ACCESS_ENABLED CRDT_ADMIN_SECRET AUTH_IDLE_TIMEOUT_MINUTES AUTH_SESSION_DAYS AUTH_REMEMBER_DAYS MAIL_ENABLED; do v="${!k}"; case "$k" in *SECRET*|*PASSWORD*) [ -n "$v" ] && echo "$k=<已设置>" || echo "$k=(未设置)";; *) echo "$k=${v:-（未设置，走代码默认值）}";; esac; done'
```

### 4.5 上线前先看一眼积压规模（只读 SQL）

这次修复之前，压缩长期失败，`crdt_update` 会一直堆积。修复后第一次压缩要一次性合并+删除，先确认规模：

```sql
SELECT COUNT(*) AS pending_updates,
       COALESCE(SUM(OCTET_LENGTH(payload)), 0) AS pending_bytes
  FROM crdt_update u
 WHERE NOT EXISTS (
   SELECT 1 FROM crdt_checkpoint c
    WHERE c.doc_id = u.doc_id AND u.id <= c.checkpoint_seq
 );

SELECT @@max_allowed_packet;
```

## 9. 导出 Word 触发退出登录：已定位（结论）

**结论：与"会话过期"无关，是导出接口本身恒返回 401。**

**证据**：用临时实例 + 刚签发的有效访问令牌，调用 `POST /api/v1/docs/{own-doc-id}/export/docx`，仍然返回 401「请先登录后再操作」；同一个令牌调用同步接口（创建文档）正常返回 200。→ 排除了会话过期、令牌失效、限流（`ApiRateLimitFilter` 只会返回 403/429）等猜测。

**因果链**：导出接口返回 `Callable` → Spring MVC 的 **ASYNC 派发**再次经过安全过滤器链 → `JwtAuthFilter`（`OncePerRequestFilter`）默认跳过 ASYNC 派发，而 Spring Security 6 的 `SecurityContextHolderFilter` 不写回上下文 → ASYNC 派发时认证信息为空 → `anyRequest().authenticated()` 失败 → 401 → 前端续期失败 → 退出登录 → 登录页再弹一条提示 → 与导出失败提示叠在一起。

**已修复**：见第 2 节「修复 10」（`JwtAuthFilter.shouldNotFilterAsyncDispatch()` 返回 false）。

**前提提醒**：这条修复**在 jar 里**，必须重新构建并重启 Java 服务才会生效。上线验证方式就是点一次导出——**能正常下载到 .docx，且不再退出登录**。
