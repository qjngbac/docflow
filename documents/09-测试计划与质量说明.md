# 云笺 DocFlow 测试计划与质量说明

## 1. 测试目标

验证账号安全、文档资产、富文本、CRDT 协作、权限、版本、导入导出、文件、反馈和管理后台在正常、异常和恢复场景下符合需求，重点防止数据丢失和越权。

## 2. 测试层级

| 层级 | 工具 | 范围 |
| --- | --- | --- |
| Java 单元/服务测试 | JUnit 5、Mockito | 权限、会话、搜索、反馈、导入导出、净化和协作服务 |
| CRDT 测试 | Node test、Y.Doc | 鉴权、并发、重复/乱序、schema 和恢复 |
| 前端工具测试 | Vitest、jsdom | 对话框、中文错误映射、内容转换 |
| API 测试 | Postman/curl | 完整业务链路、参数和权限 |
| 浏览器端到端 | 两个独立账号/浏览器 | 实时协作、分页、编辑器、反馈和后台 |
| 部署冒烟 | 真实 MySQL/Redis/SMTP | 服务启动、WebSocket、文件和导出 |

## 3. 当前自动化测试入口

```powershell
cd D:\Javaproject\docflow
mvn test

cd D:\Javaproject\docflow-collab
npm test

cd D:\Javaproject\docflow-web
npm test
npm run build
```

Java 已覆盖 AccountSecurity、AdminAuthorization、Feedback、GlobalSearch、Permission、Doc、Comment、DOCX、Export、HTML Sanitizer、CRDT Access/Checkpoint 等核心服务。CRDT 已覆盖授权、服务访问、文档状态和编辑器 schema。前端当前主要覆盖工具层，完整 UI 仍需增加 Playwright。

## 4. 测试环境

- JDK 17、Maven 3.9、Node.js 18+。
- MySQL 8，使用独立测试数据库。
- Redis 6+；协作集成测试需要两个 CRDT 节点。
- Chrome/Edge 当前稳定版。
- 测试账号：所有者 A、协作者 B、无权限用户 C、系统管理员 Admin。

## 5. 核心场景

### 5.1 认证

- 注册、登录、错误密码、封禁账号。
- Access Token 过期自动刷新；并发请求只刷新一次。
- Refresh Token 轮换、重放失败、闲置超时和绝对过期。
- 当前设备、单设备撤销、其他设备退出、密码重置撤销会话。

### 5.2 权限

- 所有者无显式权限记录仍拥有完整权限。
- READ/COMMENT/WRITE/ADMIN 的 HTTP 和 WebSocket 边界。
- 无权用户不能通过猜测 ID、全局搜索或反馈关联探测文档。
- 普通用户不能访问 `/admin/**`。

### 5.3 CRDT

- 两用户同时编辑和同位置并发编辑。
- 重复更新、乱序更新、断线重连。
- 服务重启恢复、Redis 暂时不可用和两个节点广播。
- checkpoint 成功、失败回滚、历史恢复和重复恢复。

### 5.4 编辑器与分页

- 单页/双页切换、奇数尾页、缩放和滚动条。
- 长段落跨页、不可分块、长表格按行跨页和页边距遮罩。
- 表格选择、复制粘贴、行列增删、合并拆分和宽高调整。
- 公式面板、交叉引用、脚注、文献和版本左右对比。

### 5.5 导入导出与文件

- 正常 Markdown/TXT/DOC/DOCX。
- 空文档、损坏文件、超大文件、错误 MIME 和 ZIP 炸弹。
- 危险 HTML 净化、内嵌图片、表格、公式和分页。
- 小附件、大附件分片、重复分片、合并哈希错误和超时清理。
- DOCX/PDF/HTML/Markdown/TXT 导出打开与内容核对。

### 5.6 反馈与后台

- 用户提交文字、关联文档和 0～6 张图片。
- 第 7 张图片、无权 docId、超长描述和非法类型失败。
- 管理员筛选、处理、回复和通知。
- 系统提示覆盖全部用户、精确用户名、仅开始/仅结束/完整注册时间范围以及范围内无人。
- 接收用户顶部显示提示，关闭后标记已读且刷新不再出现；多用户已读状态互不影响。
- 普通用户调用管理员发送接口返回 403；反向时间、空内容、超长内容和不存在用户名返回明确业务错误。
- 封禁立即撤销设备；管理员不能封禁自己。
- 后台进入后普通左侧导航可返回文档工作区。

## 6. 非功能测试

- 大文档连续输入、滚动和分页性能。
- 100+ 并发 WebSocket 的基线连接测试（需要专门环境）。
- DOCX、PDF 和分片上传内存/磁盘占用。
- MySQL/Redis 短暂故障、磁盘接近满、SMTP 超时。
- XSS、路径穿越、越权、弱密钥和敏感日志检查。

## 7. 测试数据

- 使用独立测试账号和邮箱，不使用生产数据。
- 文件样本包含 `DocFlow全功能导入测试.docx`、空文件、损坏 ZIP、超大压缩包、图片和长表格。
- 协作测试每次创建新文档，记录文档 ID、checkpoint 和更新数量。

## 8. 缺陷等级

| 等级 | 定义 |
| --- | --- |
| P0 | 数据丢失、任意越权、无法登录或系统整体不可用 |
| P1 | 核心协作、保存、恢复、导入导出不可用 |
| P2 | 部分编辑功能、布局或提示异常，有替代路径 |
| P3 | 文案、轻微视觉和低频兼容问题 |

## 9. 发布准入

- P0/P1 缺陷为 0。
- Java、CRDT、前端测试和生产构建通过。
- 数据库迁移在备份副本验证。
- 两账号协作、断线恢复、版本恢复、上传和导出冒烟通过。
- 管理员、普通用户和文档四级权限边界通过。
- 已知限制写入版本记录，不用“100% 无损”等不实表述。

## 10. 当前质量缺口

- 前端缺少覆盖主要页面的 Playwright 回归套件。
- 缺少真实双 CRDT 节点、Redis 和 MySQL 的自动化集成环境。
- 缺少容量压测、长期稳定性测试和性能基线。
- 缺少邮件 GreenMail 等完整集成测试和对象存储测试。
- 生产上线前必须补一次完整部署验收。
