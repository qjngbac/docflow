# 云笺 DocFlow 生产上线安全加固指南

## 1. 适用范围

本文说明当前项目从本地开发切换到公网生产环境时必须完成的安全配置。开发环境默认保留了便于 Postman、IDE 和本地文件预览的兼容设置；这些设置不能原样用于公网。

## 2. 本次已实现的安全能力

- 登录失败按账号和 IP 计数，达到阈值后要求验证码并临时锁定。
- 全局 API、认证、上传和分享接口分别限流，支持静态 IP/CIDR 黑名单。
- 失败计数和限流优先使用 Redis，多节点共享；Redis 不可用时本地开发自动退回单机内存。
- 支持 `HttpOnly + Secure + SameSite` Cookie 认证，并为修改类请求增加双提交 CSRF 校验。
- CRDT 使用仅能访问协作鉴权接口的两分钟实时令牌，避免把主访问令牌长期暴露给 JavaScript；正文快照由 CRDT 服务通过独立内部密钥回写。
- 新分享密码使用 BCrypt 保存；历史明文密码在验证成功后自动升级为 BCrypt。
- 文件检查扩展名、文件头和可执行文件特征；可接入 ClamAV 扫描病毒、木马和 Office 宏。
- 本地文件可以关闭匿名直链；公开分享中的图片改用短期 HMAC 签名 URL。
- Spring Security 增加 CSP、HSTS、X-Frame-Options、nosniff、Referrer-Policy 和 Permissions-Policy。
- 增加 Dependabot、OWASP Dependency-Check、npm audit、CodeQL、Gitleaks 和手动触发的 ZAP 基线扫描工作流。

## 3. 生产环境必须设置的变量

至少设置以下变量，不要将真实值写入 Git：

```env
APP_ENV=production

DB_USERNAME=docflow_prod
DB_PASSWORD=<数据库专用账号的高强度密码>
JWT_SECRET=<至少32字节的随机密钥>
CRDT_ADMIN_SECRET=<另一条独立随机密钥，Java与CRDT服务保持一致>
FILE_SIGNING_SECRET=<第三条独立随机密钥>

AUTH_COOKIE_ENABLED=true
AUTH_COOKIE_SECURE=true
AUTH_COOKIE_SAME_SITE=Lax
FILE_PUBLIC_ACCESS_ENABLED=false

SECURITY_TRUSTED_PROXIES=127.0.0.1/32,::1/128
SECURITY_IP_DENY_LIST=
SECURITY_STATE_FAIL_CLOSED=true

MALWARE_SCAN_ENABLED=true
MALWARE_SCAN_FAIL_CLOSED=true
CLAMAV_HOST=127.0.0.1
CLAMAV_PORT=3310

MAIL_ENABLED=true
MAIL_HOST=<SMTP地址>
MAIL_PORT=587
MAIL_USERNAME=<SMTP账号>
MAIL_PASSWORD=<SMTP授权码>
MAIL_FROM=<发件人地址>
MAIL_SMTP_AUTH=true
MAIL_STARTTLS_ENABLE=true
APP_VERIFICATION_DEBUG_CODE=false
```

数据库 URL、Redis 地址和密码也应由外部配置提供。生产数据库不要使用 `root`，只授予 DocFlow 所需库的最小读写权限。

## 4. 会影响本地运行的开关

| 配置 | 本地默认 | 生产建议 | 开启后的影响 |
| --- | --- | --- | --- |
| `AUTH_COOKIE_ENABLED` | `false` | `true` | Postman 需要保留 Cookie 和 `X-XSRF-TOKEN`；浏览器不再从存储中读取主令牌 |
| `AUTH_COOKIE_SECURE` | `false` | `true` | 只有 HTTPS 才会发送认证 Cookie，本地 HTTP 不要开启 |
| `FILE_PUBLIC_ACCESS_ENABLED` | `true` | `false` | 文件需要登录 Cookie；公开分享使用五分钟签名地址 |
| `MALWARE_SCAN_ENABLED` | `false` | `true` | 必须先运行 ClamAV/clamd，否则上传会失败或按 fail-closed 策略拒绝 |
| `MALWARE_SCAN_FAIL_CLOSED` | `false` | `true` | 扫描服务故障时拒绝上传，防止未扫描文件进入生产存储 |
| `SECURITY_TRUSTED_PROXIES` | 仅回环地址 | 实际网关地址段 | 只有可信网关发来的 `X-Forwarded-For` 才会被采用 |
| `SECURITY_STATE_FAIL_CLOSED` | `false` | `true` | Redis 安全计数不可用时拒绝请求；本地保持 `false` 可退回单机内存 |

本地不需要执行新的 SQL。本次登录保护和限流数据放在 Redis 中；分享密码字段长度已经能够容纳 BCrypt 哈希。

## 5. 网关、WAF 与 IP 黑名单

`deploy/nginx/docflow.conf.example` 提供 HTTPS 强制跳转、连接数限制、接口限流、安全响应头和 WebSocket 反向代理示例。复制后必须替换域名、证书路径和前端目录。

应用内黑名单通过 `SECURITY_IP_DENY_LIST` 配置，支持逗号分隔的单个 IP 和 CIDR。紧急封禁可同时写入服务器上的 `docflow-blocked-ips.conf` 并平滑重载 Nginx。

Nginx 不是完整 WAF。`deploy/nginx/modsecurity-main.conf.example` 提供 ModSecurity + OWASP Core Rule Set 的观察模式入口；必须先核对服务器安装路径并在测试环境验证误报，再把 `DetectionOnly` 改为 `On`。公网部署也可采用云厂商 WAF 或 Coraza，不要直接在生产环境启用未经验证的通用规则集。

## 6. 文件扫描与私有存储

生产环境运行 `clamd`，只开放给应用所在内网。DocFlow 通过 ClamAV INSTREAM 协议发送文件内容，不记录文件正文和扫描密钥。Office 宏、病毒和木马依赖病毒库识别，因此必须定期更新病毒库。

当前实现已将本地文件直链改为可关闭，并为公开分享生成短期签名 URL。正式大规模部署建议进一步把文件迁移到私有 MinIO/S3：Bucket 禁止公共读取，下载由后端签发短期预签名 URL，数据库只保存对象键而不是永久公网地址。

敏感文档还可增加 CDR（内容净化与重建）。不要把用户文件上传到公共在线扫描网站，以免造成数据泄露。

## 7. 自动化安全检查

- 每次提交和每周计划任务执行依赖审计、CodeQL 和密钥扫描。
- `Staging DAST` 只能对隔离的测试环境执行，不要把 ZAP 扫描目标指向未授权系统或生产系统。
- 扫描报告必须分级处理；高危漏洞修复后重新扫描并留存复测结果。
- CI 中使用的数据库、SMTP、对象存储和令牌全部放入平台 Secret，不写入工作流正文。

## 8. 专业渗透测试

自动化扫描不能替代人工渗透测试。正式上线前应由获得书面授权的安全人员至少覆盖认证绕过、越权访问、分享链接、文件上传、CRDT WebSocket、业务逻辑、管理后台、并发与资源耗尽。测试应在隔离环境进行，并提前约定时间、来源 IP、数据范围、禁止动作和应急联系人。

交付物至少包括漏洞复现步骤、风险等级、影响范围、修复建议、修复记录和复测结论。没有完成这一步时，只能描述为“具备基础安全加固和自动化扫描”，不能宣称“通过专业渗透测试”。

## 9. 上线核对清单

- [ ] 所有本地默认密码和密钥均已替换，三类密钥互不复用。
- [ ] HTTPS、HSTS、Cookie Secure 和反向代理已验证。
- [ ] Redis 开启认证且只允许内网访问。
- [ ] ClamAV 正常运行，使用 EICAR 测试文件验证拦截后立即删除测试文件。
- [ ] 匿名 `/files/**` 已关闭，分享图片签名过期后无法继续访问。
- [ ] 登录失败、验证码、临时锁定、IP 限流和解锁流程已测试。
- [ ] 管理后台、数据库、Redis、CRDT 管理端口均未直接暴露公网。
- [ ] 备份恢复、日志脱敏、告警通知和安全扫描报告已检查。
- [ ] 已完成授权渗透测试及漏洞复测。

## 10. 参考基线

- OWASP Authentication Cheat Sheet：登录限流、锁定和验证码属于纵深防御。
- OWASP File Upload Cheat Sheet：文件应存储在 Web 根目录之外，验证类型，并在可用时经过杀毒或沙箱扫描。
- Spring Security Reference：Cookie 认证场景必须同时考虑 CSRF，安全响应头需要由应用或边缘网关明确配置。
- OWASP ZAP：基线扫描适合作为测试环境的自动化 DAST 起点。
