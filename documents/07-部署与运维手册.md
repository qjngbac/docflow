# 云笺 DocFlow 部署与运维手册

## 1. 组件与端口

| 组件 | 默认端口 | 说明 |
| --- | --- | --- |
| Vue/Vite 开发服务 | 5173 | 开发环境前端 |
| Spring Boot | 8080 | HTTP 业务 API 与 LEGACY WebSocket |
| Spring Boot 管理端口 | 127.0.0.1:9091 | Actuator/Prometheus，仅本机或监控私网访问 |
| Hocuspocus | 1234 | Yjs CRDT WebSocket |
| CRDT 管理端口 | 127.0.0.1:1235 | checkpoint 内部管理，禁止公网暴露 |
| MySQL | 3306 | 业务与 CRDT 持久化 |
| Redis | 6379 | 多节点广播和辅助缓存 |

## 2. 环境要求

- JDK 17。
- Maven 3.6+。
- Node.js 18+、npm。
- MySQL 8.0+。
- Redis 6.0+。
- 生产环境建议 Linux、Nginx、进程守护或容器平台。

## 3. 数据库初始化

### 3.1 全新安装

创建空的 `docflow` 数据库后设置 `FLYWAY_ENABLED=true`、`FLYWAY_BASELINE_ON_MIGRATE=false`，由 Java 服务执行 `db/migration/V1__baseline.sql`。不要再手工执行 `schema.sql` 或全部历史升级脚本。

### 3.2 已有数据库升级

1. 先执行并校验完整备份。
2. 确认数据库已经是当前完整结构，而不是只执行过部分旧升级脚本。
3. 首次设置 `FLYWAY_ENABLED=true`、`FLYWAY_BASELINE_ON_MIGRATE=true`，让 Flyway 登记版本 1。
4. 成功后保持 `FLYWAY_ENABLED=true`，永久改回 `FLYWAY_BASELINE_ON_MIGRATE=false`。
5. 详细步骤、异常库处理与回滚方式见 `18-生产部署备份监控与回滚指南.md`。

首个管理员账号可在确认用户名后执行：

```sql
UPDATE `user`
SET `system_role` = 'ADMIN'
WHERE `username` = 'your_username';
```

## 5. 本地启动

启动顺序：MySQL → Redis → Java → CRDT → 前端。

```powershell
Write-Output "启动 Java 服务"
cd D:\Javaproject\docflow
mvn -pl docflow-server -am spring-boot:run

Write-Output "启动 CRDT 服务"
cd D:\Javaproject\docflow-collab
npm install
npm start

Write-Output "启动前端"
cd D:\Javaproject\docflow-web
npm install
npm run dev
```

访问 `http://127.0.0.1:5173`。

## 6. 生产部署建议

### 6.1 Nginx 路由

- `/`：前端静态资源，SPA 路由回退到 `index.html`。
- `/api/`：反代 Java 8080。
- `/files/`：由 Java 或受控文件服务提供。
- `/collab`：反代 Hocuspocus 1234，并保留 WebSocket Upgrade 头。
- 不代理 CRDT 1235 管理端口。

### 6.2 TLS 与请求限制

- 只开放 443，HTTP 重定向 HTTPS。
- CRDT 使用 WSS。
- Nginx 和 Spring 的上传大小限制保持一致。
- 设置合理代理超时，WebSocket 连接超时不能使用普通短请求值。

### 6.3 进程与扩容

- Java、前端和 CRDT 分别构建和发布。
- CRDT 多节点必须启用 Redis，每个节点使用唯一名称。
- 多节点文件上传不能继续使用各节点独立本地目录，应迁移对象存储。

## 7. 构建与测试

```powershell
cd D:\Javaproject\docflow
mvn test

cd D:\Javaproject\docflow-collab

```

构建通过不等于部署成功，还需按验收清单执行登录、文档、协作、上传和导出冒烟测试。

## 8. 健康检查与监控

建议监控：

- Java HTTP 5xx、401/403 异常增长和请求延迟。
- JVM 内存、GC、线程、Druid 连接池。
- MySQL 连接、慢查询、磁盘和备份状态。
- Redis 连接、重连和 Pub/Sub 延迟。
- CRDT WebSocket 连接数、增量写入失败、checkpoint 时长和待压缩字节。
- SMTP 失败、验证码限流、附件与反馈图片空间。
- 回收站和分片临时目录清理结果。

项目已经接入 Actuator、Prometheus 指标、Blackbox 探测和告警规则。管理端口默认只监听 `127.0.0.1:9091`，配置与告警启用方法见 `18-生产部署备份监控与回滚指南.md`。

## 9. 备份与恢复

- `deploy/scripts/backup.sh` 每日备份 MySQL 与上传目录并生成 SHA-256 校验清单。
- `docflow-backup.timer` 默认每日 02:30 执行，默认保留 14 天。
- `verify-backup.sh` 用于日常校验，`restore.sh` 需要显式确认后才会恢复。
- 恢复后先启动 MySQL/Redis/Java，再启动 CRDT；CRDT 从 checkpoint 与增量恢复。
- 恢复演练必须验证正文、权限、版本、附件 URL 和协作连接。

## 10. 发布与回滚

1. 使用 `deploy-release.sh` 在发布前生成已校验备份。
2. Java 启动时由 Flyway 验证并执行新迁移。
3. 切换版本目录并重启 Java、CRDT；前端由 Nginx 直接读取 `current/docflow-web`。
4. 健康检查失败会自动切回上一应用版本。
5. 手工回滚使用 `rollback-release.sh`；数据库恢复必须用 `restore.sh` 并停止写流量，不能直接删除未知字段。

## 11. 生产上线检查

- `JWT_SECRET` 和 `CRDT_ADMIN_SECRET` 为强随机值且彼此按要求一致。
- `APP_ENV=production`，`APP_VERIFICATION_DEBUG_CODE=false`。
- SMTP 真实发送启用并通过测试。
- `application.yml` 不含真实密码和默认弱密码。
- 数据库账号最小权限，CRDT 管理端口不暴露。
- HTTPS/WSS、CORS/CSP、备份、日志轮转和磁盘告警已配置。
- 登录失败锁定、验证码、API 限流、Cookie/CSRF、ClamAV 和私有文件访问已按 `17-生产上线安全加固指南.md` 验收。
- 已在隔离测试环境运行依赖审计、密钥扫描、代码扫描和 ZAP 基线扫描。
