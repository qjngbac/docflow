# 高级编辑与协作

## 数据库迁移

对于已有安装，请执行：

```
docflow-server/src/main/resources/db/upgrade_20260714_advanced_collaboration.sql
```

该迁移会新增以下数据表：

- `crdt_checkpoint_history`
- `document_reference`
- `attachment_upload_session`

全新安装可以直接使用 `schema.sql`，其中已经包含相同的数据库结构。

## 分页编辑

CRDT 编辑器使用浏览器的 CSS 多列分片机制，实现实时的 A4 或 Letter 纸张分页编辑。

内容块会自动流入下一个具有固定页面高度的分栏，同时整个编辑器仍然只保留一个可编辑的 Tiptap/Yjs 文档。手动分页符会强制后续内容从下一页开始。

这种实现并不是通过伪造第二个文档实现的，也不只是导出时才显示分页效果，而是真正用于实时编辑的分页布局。在浏览器布局能力允许的情况下，复杂内容块会尽量保持在同一页中，不被拆分。

对于桌面出版级别的功能，例如：

- 每页独立的页眉和页脚
- 孤行与寡行控制
- 可编辑的页面框架

应使用经过授权的专业排版引擎，例如 Tiptap Pages，或者使用专门的出版编辑器。

这些能力无法通过手写 ProseMirror 分页插件安全、可靠地重新实现。

## 公式与 MathML

公式对话框使用 MathLive 0.110.0，许可证为 MIT。

它能够以结构化方式编辑 LaTeX，并将 MathLive 生成的 MathML 与 LaTeX 备用内容一起存储在 CRDT 节点中。

公式编号和公式引用同样作为 CRDT 内容保存。

应用程序会保留受支持的 MathML，但不会声称可以对任意厂商特有的 MathML 注释进行无损转换。

## 参考文献与脚注

参考文献按文档存储在 `document_reference` 表中，格式为 CSL-JSON。

点击引用按钮后，会打开当前文档的参考文献库。用户可以：

- 选择已有的引用键
- 输入 `doi:` 加 DOI，以导入 Crossref 元数据
- 手动创建一条简化的 CSL 参考文献记录

如果网络请求失败，系统会返回业务错误，并且不会创建不完整的参考文献记录。

脚注仍然以内联 CRDT 节点的形式保存，因此脚注锚点会随着正文内容一起移动。

## 检查点历史与恢复

每次创建检查点时，系统都会将之前的快照保存到 `crdt_checkpoint_history` 表中。

历史快照的保留数量由以下环境变量控制：

```
CRDT_CHECKPOINT_HISTORY_LIMIT
```

默认值为：

```
20
```

恢复某个历史快照时，系统会先执行以下操作：

1. 断开当前活动文档的连接。
2. 从内存中卸载当前文档。
3. 将当前快照保存为 `PRE_RESTORE`。
4. 删除所选快照之后产生的增量更新。
5. 将选中的历史状态设置为当前检查点。

这样可以避免内存中仍然存在的旧文档状态，在恢复完成后再次覆盖已经恢复的快照。

## 大文件与导出

最大支持 512 MB 的附件。

对于超过 5 MB 的附件，系统会使用可恢复的分片上传会话。

浏览器会按照以下方式上传：

- 每个分片大小为 5 MB
- 同时使用 3 个上传线程

上传完成后，服务器会校验：

- 文件总大小
- SHA-256 哈希值

校验通过后，系统只会创建一条普通的 `file_attachment` 记录。

超过 24 小时未完成的上传会话会自动过期。

编辑器中的图片会使用延迟解码和 `content-visibility` 优化。

系统刻意没有对整个编辑器 DOM 使用虚拟化，因为对 ProseMirror 内容块进行虚拟化会破坏以下功能：

- 文本选择
- 输入法编辑
- 协作光标
- 实时协作状态

DOCX 和 PDF 导出目前支持映射以下内容：

- 受控的文本样式元数据
- 表格固定布局
- 公式编号标签
- 图片
- 页面尺寸
- 页面边距

但是，服务端 PDF 导出和 Apache POI 无法无损还原以下内容：

- 任意 MathLive MathML
- 仅在浏览器中生效的 CSS
- 所有 DOCX 排版特性

因此，公式在导出时会使用可读的 LaTeX 内容和公式编号作为备用显示形式。
